# 잇픽 (Eat Pick) · 저녁 메뉴 맛있는 걸로 고르기

혼자 살면서 요리를 잘 못하는 사람(요알못 나혼산)이, 최근에 먹은 메뉴를 적고 오늘 메뉴를 랜덤으로 추천받는 웹페이지입니다. 요리는 하지 않고 배달이나 외식으로 먹는 사람을 기준으로 합니다.

## 주제

저녁 메뉴를 맛있는 걸로 고르기. 최근 메뉴를 적고, 랜덤으로 저녁 메뉴를 추천받습니다. 아침·점심도 같은 방식으로 고를 수 있습니다.

## 사용 순서

1. 오늘 어떤 식사(아침·점심·저녁)를 고민하는지 고릅니다.
2. 직전 3끼에 먹은 메뉴를 적습니다. 입력 없이 다음으로 넘어가도 되고, 기억나는 것만 적으면 됩니다. 적은 메뉴는 추천에서 제외됩니다.
3. "다음: 오늘의 메뉴 고르기로"를 누르고 분야(한식·양식·일식·중식·분식)나 "랜덤"을 누릅니다. 랜덤은 5개 분야에서 모두 뽑고, 한식·양식·일식·중식·분식·최애를 똑같은 6칸으로 보고, 추천 한 번에 최애 메뉴가 하나 섞여 나올 확률은 1/6(약 16.7%)입니다. 최애 메뉴가 1개든 10개든 이 확률은 같고, 최애가 여러 개면 그중 하나가 똑같은 확률로 나옵니다. 최애 메뉴는 분야 쪽 후보에서는 빼서 따로 세므로 분야로 한 번 더 뽑히지 않습니다. 나머지 카드는 5개 분야에서 똑같은 확률로 뽑습니다. 분야를 직접 고르면 최애 메뉴 확률은 적용되지 않습니다.
4. 먹은 메뉴를 뺀 메뉴 4개를 랜덤으로 추천받습니다. 마음에 드는 메뉴를 눌러 고르고 "이걸로 정했어요"를 누릅니다. 마음에 드는 게 없으면 "다시 뽑기"로 새 4개를 받습니다. 이 화면 아래 "누적 보기"로 순위를 볼 수 있습니다.
5. 당첨 화면에서 폭죽과 함께 고른 메뉴를 보여 줍니다. 여기서 "최애 메뉴 등록하기"(뽑힌 메뉴 등록), "다른 최애 메뉴 등록하기"(목록에 있는 메뉴 이름을 입력, 최애 메뉴가 뽑힐 확률도 함께 안내), "메뉴 추가하기", "문의 남기기"를 할 수 있습니다.
6. 고른 지 3시간이 지난 뒤 다시 접속하면, 첫 화면 맨 위에서 실제로 먹었는지(YES/NO)를 묻고 먹었다면 평점(1~5점)을 받습니다. "나중에 답할게요"를 누르면 다음 접속 때 다시 묻습니다.

| 고른 식사 | 직전 3끼 (1 → 2 → 3) |
| --- | --- |
| 저녁 | 오늘 점심 → 오늘 아침 → 어제 저녁 |
| 점심 | 오늘 아침 → 어제 저녁 → 어제 점심 |
| 아침 | 어제 저녁 → 어제 점심 → 어제 아침 |

## 누적 보기

내 기기 기록과 모든 방문자의 합산을 나눠서 보여 줍니다. 내가 등록한 최애 메뉴도 함께 보여 줍니다.

- 내 기기 기록: 지금까지 먹은 메뉴 1~5위(직전 3끼에 적은 메뉴), 추천받아 선택한 메뉴 1~5위
- 모두의 기록(합산): 추천받아 선택한 메뉴 1~5위만 보여 줍니다. 직전 3끼에 적은 메뉴는 합산에 넣지 않습니다.

## 메뉴를 적을 때의 규칙

- 직전 3끼에 목록에 없는 메뉴를 적으면 입력한 이름 그대로 기록하고(분야는 기타), 추천에서만 제외합니다. 추천 후보에는 넣지 않습니다.
- 추천 후보에 넣고 싶은 메뉴는 당첨 화면의 "메뉴 추가하기"로 분야를 골라 추가합니다. 추가한 메뉴는 이 기기에서 그 분야와 랜덤 추천에 나옵니다. 같은 내용이 문의 목록에 "메뉴 추가 요청"으로도 남습니다.
- "메뉴 추가하기"는 이름만 비교해서, 같은 이름(또는 다른 표기)의 메뉴가 이미 있으면 분야가 달라도 "같은 메뉴가 있습니다."라고 알리고 추가하지 않습니다. 띄어쓰기와 대소문자는 무시합니다.
- 직전 3끼에 적은 이름이 이미 목록에 있으면 새로 만들지 않고 그 메뉴로 처리합니다.
- 철자가 조금 달라도(예: 설롱탕) 같은 메뉴(설렁탕)로 알아봅니다. 두 글자 이름은 정확히 같을 때만 같은 메뉴로 봅니다.

## 현재 상태

메뉴 추천, 기록 저장, 누적 순위, 당첨 화면, 먹었는지·평점, 문의 폼이 모두 Supabase에 연결되어 있습니다. 배포된 사이트에서 실제로 눌러 본 확인은 아직 하지 못했고, 시험은 가짜 서버와 DB 직접 조회로 했습니다.

| 항목 | 상태 |
| --- | --- |
| 화면 레이아웃 (모바일 포함), 단계 이동, 누적 보기·문의 화면 이동 | 완료 |
| 식사 선택, 직전 3끼 입력과 저장 | 완료 |
| 분야·랜덤 추천 4개 (먹은 메뉴 제외), 다시 뽑기, 이걸로 정했어요 저장 | 완료 |
| 메뉴 목록 (한식 24, 양식 15, 일식 15, 중식 13, 분식 13, 총 80개)과 메뉴별 이모지 | 초안 완료, 계속 보완 |
| 당첨 화면 (폭죽, 최애 메뉴 등록, 메뉴 추가하기, 문의 남기기) | 완료 |
| 다음 접속 때 먹었는지(YES/NO)와 평점 | 완료 |
| 같은 메뉴·비슷한 철자 알아보기 | 완료 (별칭 목록과 한 글자 차이까지) |
| 누적 보기 (내 기기 2개, 모두 합산은 선택한 메뉴만, 내 최애) | 완료 |
| 랜덤 추천 때 최애 메뉴 1/6 확률 (개수와 무관), 최애 직접 등록 | 완료 |
| 문의 폼 (4칸, Supabase 저장) | 완료 |

## 저장하는 데이터

Supabase(서울)에 저장합니다.

- `menus`: 분야별 추천 메뉴 목록, 흔한 오타·다른 표기, 메뉴별 이모지. 누구나 읽을 수 있고 쓸 수는 없습니다.
- `meals`: 먹은 메뉴(직전 3끼 입력)와 선택한 메뉴 기록. 기기 ID, 메뉴 이름, 분야, 구분(입력/선택), 시각을 담습니다. 누구나 추가할 수 있고, 기록 자체를 읽을 수는 없으며 순위 함수(`top_meals`)로 집계된 결과만 볼 수 있습니다.
- `feedback`: 고른 메뉴를 실제로 먹었는지(YES/NO)와 평점(1~5점). 넣기만 가능합니다.
- `inquiries`: 문의 폼 내용과 "메뉴 추가하기"로 들어온 메뉴 추가 요청 (아래 참고). 문의는 메일로 오지 않고 Supabase Table Editor에서 확인합니다.
- 기기 ID는 처음 접속할 때 브라우저가 만드는 임의의 값이고 이름·계정과 연결되지 않습니다. 폰과 PC는 따로 쌓이고, 브라우저 데이터를 지우면 내 기록은 새로 시작합니다.
- 최애 메뉴, 내가 추가한 메뉴, 고른 메뉴 확인 대기 상태는 이 기기 브라우저에만 저장됩니다.
- 누구나 기록을 보낼 수 있어서 합산 순위는 조작될 수 있습니다. 로그인이 없는 첫 버전의 한계입니다.

## 문의 폼

당첨 화면의 "문의 남기기"로 들어가는 별도 화면에 있습니다. 메뉴 추가 요청, 오류·불편 신고, 의견·후기를 남기는 폼이고, 보낸 내용은 Supabase의 `inquiries` 테이블에 저장됩니다. 운영자만 Supabase 대시보드에서 볼 수 있습니다. 방문자는 보내기만 되고 읽기·고치기·지우기는 막혀 있습니다(RLS). 답장은 하지 않아서 이름·이메일은 받지 않습니다.

| 칸 | 입력 방식 |
| --- | --- |
| 문의 종류 | 선택: 메뉴 추가 요청 / 오류·불편 신고 / 의견·후기 |
| 내용 | 자유 입력 (1000자까지) |
| 쓰는 기기 | 선택: 폰 / PC |
| 만족도 | 선택: 1~5점 |

- 메뉴 이름과 분야 칸은 없습니다. 메뉴를 추가해 달라는 문의는 내용 칸에 적고, "메뉴 추가하기" 버튼으로 추가한 메뉴는 이름과 분야가 함께 저장됩니다.
- 모든 칸은 비워 둘 수 있지만, 전부 비어 있으면 보낼 수 없습니다.
- 버튼 문구는 "잇픽에 보내기", 접수 문구는 "응답이 접수되었습니다. 의견 남겨주셔서 고마워요:)"입니다.
- 스팸 방지: 사람 눈에 보이지 않는 숨김 칸이 채워지면 저장하지 않고, 페이지를 연 지 3초 안에 보내면 막습니다. 단순한 자동 입력만 막을 수 있어서, 스팸이 실제로 오면 캡차를 추가합니다.
- 페이지 코드에 들어 있는 키는 공개용(publishable) 키입니다. secret 키와 service_role 키는 절대 코드에 넣지 않습니다.
