# 잇픽 (Eat Pick) · 저녁 메뉴 정하기

혼자 살면서 요리를 잘 못하는 사람(요알못 나혼산)이, 최근에 먹은 메뉴를 빼고 오늘 저녁 메뉴를 추천받는 웹페이지입니다.

## 왜 만들었나

저녁 메뉴를 정할 때 최근에 먹지 않은 메뉴가 바로 떠오르지 않습니다. 지금은 머릿속 기억으로 고르고, 안 떠오르면 간단히 때웁니다. 이 페이지는 그 과정을 줄이려는 것입니다.

## 사용 순서

1. 최근 며칠간 먹은 저녁 메뉴를 고릅니다. 목록에 없으면 "기타"에 이름을 씁니다. 분야는 기타로 들어가고, 나중에 원하는 분야로 바꿀 수 있습니다. 이미 있는 메뉴이거나 철자가 조금 다르면(예: 설롱탕) 새로 추가하지 않고 기존 메뉴(설렁탕)로 처리합니다. 두 글자 이름은 정확히 같을 때만 같은 메뉴로 봅니다. 먹은 날(오늘·어제·그저께)도 고를 수 있고, 건너뛰면 오늘로 기록합니다.
2. 오늘 땡기는 분야를 누릅니다. 한식, 양식, 일식, 중식, 분식, 기타 중에서 고릅니다. 기타는 직접 추가한 메뉴에서 추천합니다.
3. 먹은 메뉴를 뺀 저녁 메뉴 4개를 랜덤으로 추천받습니다.
4. 마음에 드는 메뉴가 없으면 "다시 뽑기"로 새 4개를 받습니다. 이전에 나온 메뉴가 더 마음에 들면 기타에 그 메뉴를 쓰고 선택합니다.
5. "이걸로 정했어요"를 눌러 최종 선택합니다.
6. "누적 보기"를 누르면 먹은 횟수 기준 베스트 1~5위를 볼 수 있습니다.

## 현재 상태

지금은 화면만 있습니다. 버튼은 모양만 있고 눌러도 동작하지 않습니다(누적 보기 펼치기만 동작).

| 항목 | 상태 |
| --- | --- |
| 화면 레이아웃 (모바일 포함) | 완료 |
| 먹은 메뉴 선택, 기타 입력칸, 날짜 고르기 | 화면만 있음, 동작 연결 전 |
| 분야 선택 버튼 6개 | 화면만 있음, 동작 연결 전 |
| 추천 4개, 다시 뽑기, 이걸로 정했어요 | 화면만 있음, 동작 연결 전 |
| 분야별 추천 메뉴 목록 (한식·양식·일식·중식·분식, 약 60~100개) | 미작성 |
| 기타 메뉴의 분야 바꾸기 | 화면만 있음, 동작 연결 전 |
| 누적 보기 (베스트 1~5위) | 예시 값만 있음, 저장 연결 전 |
| 문의 폼 (6칸, Supabase 저장) | 연결 완료 |

화면에 보이는 "메뉴 A~D" 등은 예시 값이며 실제 메뉴가 아닙니다.

## 저장하는 데이터

- 먹은 메뉴 기록: 메뉴 이름과 먹은 날짜. 같은 날 같은 메뉴는 한 번만 셉니다.
- 먹은 횟수: 먹은 메뉴 기록에서 센 메뉴별 횟수
- 기타 메뉴: 직접 쓴 메뉴 이름과 분야. 처음엔 분야가 기타이고, 사용자가 원하는 분야로 바꿀 수 있습니다. 추천 후보와 먹은 메뉴 선택 칩에 추가됩니다. 이름이 목록의 메뉴와 같거나 철자가 비슷하면 추가하지 않습니다.
- 분야별 메뉴 목록: 페이지에 미리 넣어 둔 고정 목록

저장 위치는 사용자 각자의 기기 브라우저입니다. 사용자마다 따로 저장되어 서로 섞이지 않습니다. 브라우저 기록을 지우면 누적 데이터도 사라지고, 다른 기기에서는 보이지 않습니다.

## 문의 폼

방문자가 메뉴 추가 요청, 오류·불편 신고, 의견·후기를 남기는 폼입니다. 보낸 내용은 Supabase의 `inquiries` 테이블에 저장되고, 운영자만 Supabase 대시보드에서 볼 수 있습니다. 방문자는 보내기만 되고 읽기·고치기·지우기는 막혀 있습니다(RLS). 답장은 하지 않아서 이름·이메일은 받지 않습니다.

| 칸 | 입력 방식 |
| --- | --- |
| 문의 종류 | 선택: 메뉴 추가 요청 / 오류·불편 신고 / 의견·후기 |
| 내용 | 자유 입력 (1000자까지) |
| 메뉴 이름 | 직접 입력 (50자까지) |
| 분야 | 선택: 한식·양식·일식·중식·분식·기타 |
| 쓰는 기기 | 선택: 폰 / PC |
| 만족도 | 선택: 1~5점 |

모든 칸은 비워 둘 수 있지만, 전부 비어 있으면 보낼 수 없습니다. 버튼 문구는 "잇픽에 보내기", 접수 문구는 "응답이 접수되었습니다. 의견 남겨주셔서 고마워요:)"입니다.

페이지 코드에 들어 있는 키는 공개용(publishable) 키입니다. secret 키와 service_role 키는 절대 코드에 넣지 않습니다.

## 하지 않는 것

- 요리법과 장 볼 재료 안내 (배달이나 외식으로 먹는 사용자 기준)
- 취향 맞춤 추천 (추천은 랜덤이고, 누적 데이터는 보여 주기만 합니다)
- 영양·칼로리 표시 (다음 버전 후보)

다음 버전 후보: 로그인·계정, 음식 사진 (첫 버전은 이모지로 시작)

## 파일

- `index.html`: 화면 (HTML 파일 하나로 동작, 별도 설치 불필요)

브라우저에서 파일을 열면 바로 확인할 수 있습니다. GitHub Pages로 올리면 `index.html`이 첫 페이지로 열립니다.

## 앞으로 할 일

- 분야별 추천 메뉴 목록 채우기 (약 60~100개)
- 먹은 메뉴를 제외하고 랜덤 4개를 추천하는 동작, 다시 뽑기, 최종 선택 연결
- 먹은 메뉴 기록 저장과 베스트 1~5위 표시
- 다음 버전: 로그인·계정, 음식 사진, 영양·칼로리
