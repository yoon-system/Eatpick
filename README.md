# 잇픽 (Eat Pick) · 저녁 메뉴 맛있는 걸로 고르기

혼자 살면서 요리를 잘 못하는 사람(요알못 나혼산)이, 최근에 먹은 메뉴를 적고 오늘 메뉴를 랜덤으로 추천받는 웹페이지입니다. 요리는 하지 않고 배달이나 외식으로 먹는 사람을 기준으로 합니다.

## 주제

저녁 메뉴를 맛있는 걸로 고르기. 최근 메뉴를 적고, 랜덤으로 저녁 메뉴를 추천받습니다. 아침·점심도 같은 방식으로 고를 수 있습니다.

## 사용 순서

1. 오늘 어떤 식사(아침·점심·저녁)를 고민하는지 고릅니다.
2. 직전 3끼에 먹은 메뉴를 적습니다. 고른 식사에 따라 직전 3끼가 달라집니다. 기억나는 것만 적어도 되고, 입력 없이 다음으로 넘어가도 됩니다. 적은 메뉴는 추천에서 제외됩니다.
3. "다음: 오늘의 메뉴 고르기로"를 누르고, 지금 땡기는 분야를 누릅니다. 한식, 양식, 일식, 중식, 분식, 기타 중에서 고릅니다.
4. 먹은 메뉴를 뺀 메뉴 4개를 랜덤으로 추천받습니다. 마음에 드는 메뉴가 없으면 "다시 뽑기"로 새 4개를 받고, 정했으면 "이걸로 정했어요"를 누릅니다.
5. 첫 화면 맨 아래 "누적 보기 · 문의 남기기"를 누르면 두 번째 페이지가 열립니다. 누적 순위를 보거나 문의를 남길 수 있습니다.

| 고른 식사 | 직전 3끼 (1 → 2 → 3) |
| --- | --- |
| 저녁 | 오늘 점심 → 오늘 아침 → 어제 저녁 |
| 점심 | 오늘 아침 → 어제 저녁 → 어제 점심 |
| 아침 | 어제 저녁 → 어제 점심 → 어제 아침 |

## 누적 보기

두 가지를 따로 정리합니다. 각각 1~5위를 보여 줍니다.

- 지금까지 먹은 메뉴: 직전 3끼에 적은 메뉴를 저장해서 센 순위
- 추천받아 선택한 메뉴: "이걸로 정했어요"로 고른 메뉴를 센 순위

## 메뉴를 적을 때의 규칙

- 목록에 없는 메뉴를 적으면 처음에는 분야가 "기타"로 들어가고, 추천 후보에 추가됩니다. 나중에 원하는 분야로 바꿀 수 있습니다.
- 적은 이름이 어느 분야 목록에든 이미 있으면 새로 추가하지 않고 그 메뉴로 처리합니다.
- 철자가 조금 달라도(예: 설롱탕) 같은 메뉴(설렁탕)로 알아봅니다. 두 글자 이름은 정확히 같을 때만 같은 메뉴로 봅니다.

## 현재 상태

지금은 화면만 있고, 문의 폼만 실제로 동작합니다. 추천과 저장 버튼은 눌러도 동작하지 않습니다. 화면 이동(단계 넘기기, 두 번째 페이지)은 동작합니다.

| 항목 | 상태 |
| --- | --- |
| 화면 레이아웃 (모바일 포함), 3단계 이동, 두 번째 페이지 이동 | 완료 |
| 식사 선택, 직전 3끼 입력칸 | 화면 완료, 저장·추천 제외 동작은 연결 전 |
| 분야 선택 버튼 6개 | 화면 완료, 누르면 다음 단계로 넘어가기만 함 |
| 추천 4개, 다시 뽑기, 이걸로 정했어요 | 화면만 있음, 동작 연결 전 |
| 기타 메뉴 분야 바꾸기 | 화면만 있음, 동작 연결 전 |
| 분야별 추천 메뉴 목록 (한식·양식·일식·중식·분식, 약 60~100개) | 미작성 |
| 누적 보기 (순위 2개) | 예시 값만 있음, 저장 연결 전 |
| 문의 폼 (6칸, Supabase 저장) | 연결 완료 (배포된 사이트에서 실제 전송 확인은 아직) |

화면에 보이는 "메뉴 A~J" 등은 예시 값이며 실제 메뉴가 아닙니다.

## 저장하는 데이터 (연결 예정)

- 먹은 메뉴 기록: 메뉴 이름과 먹은 때(오늘·어제, 아침·점심·저녁). 같은 날 같은 메뉴는 한 번만 셉니다.
- 선택한 메뉴 기록: "이걸로 정했어요"로 고른 메뉴
- 기타 메뉴: 직접 적은 메뉴 이름과 분야. 처음엔 분야가 기타이고 나중에 바꿀 수 있습니다.
- 분야별 메뉴 목록: 페이지에 미리 넣어 둔 고정 목록 (기타 메뉴는 별도)

저장 위치는 사용자 각자의 기기 브라우저입니다. 사용자마다 따로 저장되어 서로 섞이지 않습니다. 브라우저 기록을 지우면 누적 데이터도 사라지고, 다른 기기에서는 보이지 않습니다.

## 문의 폼

두 번째 페이지에 있습니다. 메뉴 추가 요청, 오류·불편 신고, 의견·후기를 남기는 폼이고, 보낸 내용은 Supabase의 `inquiries` 테이블에 저장됩니다. 운영자만 Supabase 대시보드에서 볼 수 있습니다. 방문자는 보내기만 되고 읽기·고치기·지우기는 막혀 있습니다(RLS). 답장은 하지 않아서 이름·이메일은 받지 않습니다.

| 칸 | 입력 방식 |
| --- | --- |
| 문의 종류 | 선택: 메뉴 추가 요청 / 오류·불편 신고 / 의견·후기 |
| 내용 | 자유 입력 (1000자까지) |
| 메뉴 이름 | 직접 입력 (50자까지) |
| 분야 | 선택: 한식·양식·일식·중식·분식·기타 |
| 쓰는 기기 | 선택: 폰 / PC |
| 만족도 | 선택: 1~5점 |

- 모든 칸은 비워 둘 수 있지만, 전부 비어 있으면 보낼 수 없습니다.
- 버튼 문구는 "잇픽에 보내기", 접수 문구는 "응답이 접수되었습니다. 의견 남겨주셔서 고마워요:)"입니다.
- 스팸 방지: 사람 눈에 보이지 않는 숨김 칸이 채워지면 저장하지 않고, 페이지를 연 지 3초 안에 보내면 막습니다. 단순한 자동 입력만 막을 수 있어서, 스팸이 실제로 오면 캡차를 추가합니다.
- 페이지 코드에 들어 있는 키는 공개용(publishable) 키입니다. secret 키와 service_role 키는 절대 코드에 넣지 않습니다.
